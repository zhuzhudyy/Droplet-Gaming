本任务是实际实施任务，不是再次输出计划。
根据 ArtSource/References/space_environment_reference.png，先在 Blender 中完成太阳、地球、小行星带和背景的几何建模与空间搭建，自检通过后，再导出并导入现有 Unity 项目。

本轮只完成“几何、布局、基础外观、资产复用和导入验证”。不做正式光效，不增加游戏玩法，不重新实施 G00–G09。

## 2. 要保留的画面与本轮不做的内容

参考画面的核心是：左上太阳、右侧地球、左上向右下横贯画面的斜向小行星带、左下/右下少量前景大岩石，以及远处黑色星空。

设置一个 16:9 的 ReferenceCamera；以下为可调整的屏幕构图起点，坐标原点在画面左上，不是世界坐标：
- 太阳中心约 (0.16, 0.22)，可见球体直径约画面高度的 12%–15%，不含原图光晕。
- 地球中心约 (0.83, 0.39)，球体直径约画面高度的 16%–19%。
- 小行星带由左侧约 0.25 高度向右侧约 0.65 高度延伸；使用有厚度、密度变化的弧形空间带，不做一条实心圆环。
- 少量大岩石位于左下、右下边缘，建立前后层次，不能用大石头堵满中央可玩区域。
- 主体天体轮廓、大小关系、岩带走势和留白优先于逐块复刻碎石。

这是可从不同方向观察的游戏环境，不是只在一台相机前成立的舞台布景。相机转动后仍应合理，但不要求太阳和地球始终停在固定屏幕坐标。

本轮不建水滴、星舰、爆炸、烟雾或战斗残骸。图中其他小球体、遥远星系细节可省略，不猜测它们是哪颗行星。不把小行星带做成贴着地球的行星环。

暂不制作太阳发光、日冕、Bloom、镜头光斑、丁达尔光、体积雾、银河雾、地球大气散射、反射探针、烘焙照明或后期处理。
允许为模型识别创建基础底色、UV 和小尺寸基础贴图；这些不是本轮的最终美术材质。
预览使用 Blender Solid/Workbench 的中性棚拍显示，Unity 使用 Unlit 基础材质或隔离的临时检视灯。临时灯不导出，不并入正式环境 Prefab，不修改正式关卡的灯光。

## 3. 内存与几何预算

以下是本轮起始设计预算，不是已测性能，也不是整款游戏总预算。读取现有游戏尺度与活动边界；默认复用本批配置，不修改玩家速度、碰撞半径、舰船尺寸或任务逻辑。

- 太阳：一个低面数平滑球体，约 1,000–2,000 三角形。
- 地球：LOD0 约 4,000–8,000 三角形，LOD1 不超过 2,000，LOD2 不超过 600。若更简单模型已满足参考屏幕尺寸，直接用更简单的。
- 小行星：8 个可辨认的共享形状原型。每个 LOD0 约 800–2,000 三角形、LOD1 约 200–500、LOD2 约 40–120。
- 默认近景 12 个实例，中景 160 个实例；可依据构图在近景 8–16、中景 120–200 范围调整。
- 远景细小岩石用低多边形轮廓或少量分区组合网格表示，默认 6–8 个空间分区，总三角形优先控制在 15,000 内。不为每个远景点创建 GameObject。
- 本环境唯一网格三角形合计目标不超过 60,000，统计包含所有 LOD 与远景组合网格。
- 参考视点实际提交的环境三角形目标不超过 180,000；在可玩区域抽样视点尽量不超过 250,000。
- 岩石使用 1–2 套共享材质，全环境基础材质目标不超过 6 个。
- 地球基础色贴图默认 2048×1024；可选星空贴图最多 2048×1024；岩石默认使用基础色/顶点色，确有必要再加一套共享的 1024 级贴图。太阳先不需要专用贴图。
- 禁止为每个实例创建独立贴图；不制作 4K/8K 贴图、每颗岩石独立贴图集、实时高细分或毛发/粒子石海。
- 本环境 Mesh 和 Texture 的可归因驻留资源预算暂以 64 MiB 为目标，系统内存与可获得的显存数据分别记录；这不是承诺，也不是用包体大小推算的结果。

LOD 用于降低远处的绘制复杂度；不得假设切换 LOD 后高精度网格就已从内存卸载。报告要区分唯一资源量、实例数量、当前绘制量和运行时内存。
LOD0 只用于实际需要的近景；不要把全部岩石都绑定到最高精度。
不足以测量内存时，给出资源清单、平台纹理格式、包含 mipmaps 的估算方法和未测项，不编造“总共只占多少 MB”或保证帧率。

## 4. Blender：制作资产

太阳：
- 制作 UV 正确、法线向外、轮廓平滑的球体，原点在球心。
- 使用非发光的黄白基础色，不制作火焰几何、凸起噪声或灯光组件。

地球：
- 制作低面数平滑球体，球心原点，合理 UV；检查两极、接缝和贴图朝向。
- 大陆、海洋和云层主要由一张基础色贴图表达，不把山脉、云朵或大陆轮廓挤出为几何。
- 优先复用项目已有且来源明确的地球贴图；否则可取得许可明确的低分辨率地球底图并记录来源。没有可用底图时允许临时替代，但必须标注，不能把随机噪声大陆称为准确地球。
- 云层先合入基础色；不增加透明云球、大气外壳或复杂夜面材质。本轮不把方向性阴影或太阳辉光烘焙进基础色。

小行星：
- 8 个原型至少覆盖近圆块、长条块、扁平块、棱角块及明显凹缺口的轮廓差异。
- 用有限分辨率的非均匀形变、切削和大中尺度凹凸形成自然形状；不要只是等比例缩放同一个球。
- 保留近景可读的大凹坑、断面和边缘，不用真实几何制作密集微小裂缝。
- 若使用高模雕刻/位移，只作有限的离线辅助，最终导出满足预算的低模。
- LOD 间保持中心、主方向和主要轮廓一致；在实际参考相机下查看切换是否明显。
- 在 Blender 中通过 linked mesh/实例复用原型；通过旋转、正值缩放和少量共享色差降低重复感。
- 原型对象应用必要变换，保持导出契约一致；摆放实例允许不同变换，但不要为应用实例缩放而复制成独有网格。
- 不给每个实例保留一套昂贵且独立求值的几何节点、布尔或细分修改器。

星空：
- 可制作共享低面数天空穹顶及一张简单、无方向性照明的基础星点贴图，或复用已有轻量方案。
- 不为每颗恒星建球、建灯，不做体积银河。
- 禁止把整张参考图贴到一个平面或直接包成天空球来冒充三维建模；16:9 参考图也不能直接当作完整 360 度全景贴图。
- 太阳、地球和近中景岩石必须是可独立选中与编辑的真实三维对象。

## 5. Blender：完成整体搭建后再导入 Unity

在 Blender 中保存完整、可编辑的 SpaceEnvironment.blend，并包含清晰集合：
- CelestialBodies：太阳、地球。
- AsteroidLibrary：共享原型与 LOD，独立隐藏展示，避免重复出现在场景中央。
- AsteroidBelt_Near / Mid / Far：实例与远景分区。
- GameplayReserve：可玩区和安全距离标记，不渲染、不导出为碰撞物。
- ReferenceCameras：参考相机与检查视点。
- PreviewOnly：仅供预览的对象，不进入游戏资产。

基于现有任务活动区域，建立明确的无障碍可玩空间，并考虑相机跟随距离与岩石自身半径留出余量。近景岩石在画面上可显得大，但不得占据既有舰队或玩家主要路线。

天体采用有限尺度的远景代理，保持参考视角下的角大小与方位。不用天文单位直接摆放，不为了构图把坐标和裁剪距离扩大许多个数量级，不新建完整太阳系模拟或无限空间系统。

本轮不增加背景碰撞。太阳、地球和岩石均为装饰层，不能被计分、摧毁或当成任务目标。不得用单纯关闭 Collider 掩盖石块堵住航道的问题。

布局参数集中保存：随机种子、密度、尺寸范围、排除区域、天体位置、相机与各区预算。固定种子确保重跑可复现。
生成器只更新明确归属本任务的对象，不删除其他集合或手工内容。

Blender 自检完成前，不进入 Unity 集成阶段。至少完成：
- 保存并重新打开 .blend，确认资产和基础纹理引用存在。
- 参考视角构图检查，以及侧面/俯视检查；不是只看一张渲染。
- 线框检查、法线检查和三角形统计。
- 检查实例是否共享网格、是否有重叠的 LOD 一起显示。
- 查看靠近岩带和从可玩区转向时的三维关系。
保存证据截图；没有图像查看能力时，区分“截图已生成”和“已实际检查”。

## 6. 导出：原型与布局分开

优先复用项目已有且验证过的 Blender → Unity 流程。
参考图和 .blend 源文件保存在 Assets 之外；只把实际需要的模型、贴图和布局文件送进 Unity。

输出可包括：
ArtSource/Blender/SpaceEnvironment/SpaceEnvironment.blend
Tools/Blender/SpaceEnvironment/ 下的生成、验证、导出脚本及配置
Assets/_Project/Art/Environment/SpaceEnvironment/ 下的 Models、Textures、Layout

核心约束：
- 太阳、地球、每个岩石原型及其 LOD 各导出一次。
- 布局只记录稳定 instanceId、assetId 和位置/旋转/缩放，不为每个摆放实例重复导出完整岩石网格。
- 远景分区组合网格可以分别导出，但必须计入唯一几何预算，并保持分区剔除能力。
- 优先沿用已有 Empty 标记 FBX 导入器；若现有系统使用 JSON 布局则沿用，不另造两套权威布局。
- 采用单位/方向校准物与不对称标记验证导出；不能通过给 Unity 每个对象随便转 90 度“修好”。
- 只应用一次坐标系转换，明确布局是局部还是世界坐标；防止模型和布局重复缩放或翻转。
- 基础贴图为独立文件，避免每个 FBX 内重复嵌入同一张图。
- 不假定 Blender 节点材质会完整进入 Unity，基础材质在 Unity 中显式映射。
- 不手写、猜测 .meta GUID 来伪造资产引用，使用现有可靠工具和 Editor API。

## 7. Unity：完成真实导入、复用与保存

在 Blender 阶段通过后，才执行本阶段。
创建或安全更新：
- Assets/_Project/Prefabs/Environment/SpaceEnvironment.prefab
- Assets/_Project/Scenes/SpaceEnvironment_Review.unity

如果项目已存在相同用途的目录/资产，可遵循现有约定并记录准确位置。
正式 FleetAssault/TestRange 的玩法、灯光和对象保持不变；本轮先交付独立检视场景和可复用环境 Prefab，不自动替换正式关卡。

通过 Editor 工具把 Blender 布局转换成保存的对象层级。重复导入只更新工具自有根节点，不重复产生天体、岩石、材质或 Prefab，也不删除外部手工内容。
太阳、地球、原型与布局实例均应在不按 Play 时可见、可编辑；不靠 Awake/Start 临时生成整片背景。

内存与导入要求：
- 同型岩石、同一级 LOD 引用相同 Mesh；相同外观引用共享 Material。检查实际引用，而不只检查名字。
- 避免访问/创建会产生每实例独有网格和材质的副本；不把数百块共享岩石变成数百份资源。

- 背景网格无运行时读写需求时关闭 Read/Write；基础贴图也关闭无必要的 CPU 读写副本。
- 关闭背景模型不需要的骨骼、动画、BlendShape 和光照贴图 UV 导入/生成。
- 使用目标平台合适的纹理压缩，记录实际格式和导入后的尺寸；保留需要的 mipmaps 并计入资源预算。
- 不对重复岩石整批盲目开启 Static Batching，不复制几何来换取表面的批次数下降。
- 优先沿用当前渲染管线的兼容批处理机制，观察真实行为；不宣称仅勾选 GPU Instancing 就一定合批或零开销，也不为此迁移渲染架构。
- 配置已有兼容 LOD 方案；按实际屏幕占比检查。消失阈值不要让显眼的大石头突然消失，不使用超大整体包围盒破坏分区剔除。
- 不添加 Bloom、体积效果、反射或地球大气 Shader；基础 Unlit 显示只用于检查构图和贴图识别。
- 不修改正式场景摄像机参数；检视相机记录其视角与裁剪设置，检查近距离裁剪与球体被切掉的问题。

## 8. 验证与交付终点

实际执行：
1. Blender 生成、保存、重开、导出全部成功；不以“脚本写好”代替资产生成。
2. Unity 本机导入和编译检查，无缺失网格、材质、贴图或脚本。

5. 重复导入两次、重开检视场景，数量、稳定 ID 与共享引用正确；外部手工对象保留。
6. 检查 LOD 切换、剔除、导入后的顶点/三角形、材质与纹理数量。
7. 检查背景不属于攻击目标，不修改原有核心玩法。
8. 记录工具实际可取得的 Mesh/Texture 与整体内存数据。Editor 中取得的数据标注为 Editor；资源估算和独立运行实测严格区分。
