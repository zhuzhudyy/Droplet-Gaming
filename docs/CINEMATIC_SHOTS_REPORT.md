# Combat close-ups — 2026-09-19

Implemented against Unity 6000.5.10f1, URP 17.5.0 and Input System 1.20.0. The project has no installed Cinemachine package, so the existing `ChaseCamera` is extended without replacing the camera system. Root owns final scene wiring, actual Editor execution, the full 2000-ship player and acceptance evidence.

## Integration and controls

Add `ShotDirector` to the new scene and call `Configure(mission, simulation, chase, fleetRenderer)`. Add one `CombatListenerAnchor`, assign its `chase`, and move the sole enabled `AudioListener` from the camera to that anchor using Editor APIs. Set `fleetRenderer.normalStreamingReference = anchor.transform` to retain the normal streaming neighbourhood throughout both shots and return blends.

F8 cycles **Off / Low / Standard**. Q returns to flight view over 0.24 seconds and does not occupy Space/brake. The return action is an independent Input System binding exposed as `returnBinding` and through `RebindReturn(string)`. HUD remains visible. The lower-right status label displays frequency and the bound return control during a shot. `SetFrequency` is also available to an authored menu.

## Delivered behaviour

- Subscribes to the existing `FleetCombatSimulation.EventRaised`: WeaponFired → attacker/muzzle; DropletContact → droplet surface; HullPenetrated with Penetration source → oblique flyby; ShipExploded → actual explosion position. The legacy HullPenetrated label also covers laser hull damage, which is explicitly excluded from droplet fly-through shots. No new gameplay event bus, replayed damage, delayed explosion or synthetic weapon event.
- Importance, distance, normal-view visibility, recent shot-kind repetition and stable subject-ID repetition affect probabilistic selection. A private PRNG avoids consuming any gameplay random state. Standard cooldown is 12–20 simulation seconds; Low multiplies it by 1.7 and lowers selection probability. Attacker and contact share one ordinary opportunity per **1.5 seconds**, with an additional **0.25** probability-weight factor independent of major events. Eligible ordinary notifications in that opportunity's rendered frame reuse the same random draw and compete through the existing highest-weight candidate; this prevents the WeaponFired callback from permanently excluding its immediately following DropletContact. Rare events retain their own 0.2-second sampling windows. The previous shot kind is excluded for 32 seconds. These gates discard current notifications and never schedule a later cut; a high fire rate cannot buy unlimited selection attempts and monopolize every cooldown opening.
- An explosion behind the normal flight view retains a facing weight of at least **0.9**, instead of the ordinary event minimum of 0.45. A delayed blast commonly falls behind a moving droplet; the new shot still has to pass its own actual hull-occlusion and composition tests. Distance limits, the 12–20-second global cooldown, event age and damage timing remain unchanged. No missed-event compensation queue or replay mechanism is added.
- When an actual FatalPending ship is within 1600 Unity units of the droplet and its unchanged explosion deadline is 0–5 simulation seconds away, only the current attacker/contact selection weight is multiplied by **0.18**. This leaves more opportunities for the real explosion notification. Distant pending ships do not suppress local contact shots. The global cooldown is unchanged; there is no reserved shot, future-event queue, early explosion or damage mutation.
- Attacker composition chooses between the ship's left/right oblique positions using the existing `RenderSettings.sun` direction. It prefers the more illuminated side, falls back to the opposite side if the authoritative hull query blocks the preferred view, and rejects both if neither is clear. The selected side stays fixed throughout the shot; new occlusion ends the shot instead of flipping the view. No light, light setting or material is added or changed.
- A single strongest candidate can survive only within its original rendered frame. Attack/contact notifications expire after 0.14 seconds; penetration/explosion after 0.24 seconds. There is no backlog. The initial 0.75 seconds is quiet.
- Normal durations are contact 0.65 seconds, attacker/penetration 0.85 seconds and explosion 1.1 seconds. Invalid subject, occlusion, strong turn, teleport, pause, story, results or mode Off can end a shot sooner. Strong turning suppresses selection for 0.65 seconds. Angular velocity uses the larger of the render interval and the motor's actual simulation interval, so a short high-FPS render frame cannot exaggerate a fixed-step rotation. The authoritative fleet raycast includes occluding distant ships whose Unity colliders are streamed out.
- `ChaseCamera` continuously maintains its independent normal pose. The camera never rotates the droplet or modifies flight input, speed, time scale, damage, score or explosion deadlines. Its return blend is relative to the moving normal chase pose, avoiding high-speed world-position lag.
- Listener stays at the normal chase pose. When narrative disables the chase camera, the listener computes this pose from the moving droplet instead of retaining the old combat spawn. Only the selected live ship is temporarily forced to LOD0; the rest retain existing tiers. Clear/disable/reset restores automatic LOD. The permanent normal streaming reference also covers return blending.
- Distant pinning now activates the selected full prefab before calling native `ForceLOD(0)`. Destruction can deactivate the group before shot cleanup; that cleanup defers `ForceLOD(-1)` until the target's real restoration, without reactivating a destroyed hull. The one-shot release also survives disabling the optional fleet renderer before restart. Normal scenes which never pin a subject make no additional native ForceLOD calls.
- Active subject identity, generation, damage state, escape state and simulation membership are checked. Subject restoration cancels immediately. Explosions use immutable event positions rebased through accumulated origin offsets, never a pooled explosion transform. Attacker tracking uses an initial local muzzle point on the validated subject.
