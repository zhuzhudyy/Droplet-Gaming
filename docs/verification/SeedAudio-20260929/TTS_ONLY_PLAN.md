# 全音频由 Seed-TTS 2.0 生成 — 实施计划

用户于 2026-09-29 授权实施。本计划替代此前 BytePlus / Seed Audio 1.0 方案。
状态（2026-09-29 实测后）：**代表素材门槛未通过，暂停扩量**。19 次请求产出 17 个原始 WAV；六类各完成最多三次尝试，仍有提示词朗读证据及听感未确认项。不得据有效 WAV 进入批量制作或 Unity 发布。结果见 [验收报告](verification/SeedTTS-Soundscape-20260929/REPORT.md)。以下保留用户授权的完整制作范围。

## 唯一生成路线与预算

- 所有对白、音乐、环境声和细节音效仅使用 Seed-TTS 2.0。
- 复用 `Tools/Audio/volc_voice.py`、Agent Plan `/api/v3/plan/tts/unidirectional` 和本机 `VOLC_SPEECH_API_KEY`；密钥不得进入聊天、Assets、源码或日志。
- Codex 负责提示词、候选筛选、修订、后期和 Unity 接入。本地工具只裁切、调音、循环处理及混合 Seed-TTS 产物，不合成替代声源。
- 本任务累计上限 20,000 AFP，包含测试和重做；不充值、不启用超额付费、不更换供应商。
- 费用账本区分服务返回用量、按官方系数折算的 AFP 和无法确认的消耗；估算不冒充控制台账单。

## 先测试，再扩大

1. 先预览请求，再用现有密钥生成约五秒英语对白，核查鉴权、完整 PCM 和用量。
2. 验证激光、金属贯穿、爆炸、飞行持续声、舰内环境、无歌词背景音乐六类代表。
3. 分别组织非空合成文本与 `context_texts` 表演指令，不重复此前空文本失败探测；不虚构 API 参数。
4. 每类先做一条，质量不合格最多再做两轮提示词修订。身份验证/配额错误停止请求；不确定提交不自动重发。
5. 保存请求、原始音频、检查结果和失败原因。检查误读提示词、旁白污染、明显口技、失真、起音尾音、时长和循环适用性。
6. HTTP 成功和技术检查不能代替声音内容验收。六类代表全部合格后，才进入批量生成及 Unity 应用；未合格项保留证据，停止扩量，不标记完成。

## 工具与 Unity 接入（代表素材通过后）

- 用批次清单、可恢复用量账本及完成状态+文件哈希共同管理生成。预览不读密钥、不联网、不写文件；生成、检查、发布分离。
- 新资源先留在 Assets 外的暂存目录，验收后由根统一通过 Unity Editor API 导入，并制作当前正式场景的安全副本。保留原场景、GUID 和无关未提交工作。
- 新增声音目录配置，以及阶段背景、运动和界面/任务音频组件；战斗复用已有稳定 eventId / generation / originOffset 事件。
- Motor 只发布已消费操控的只读状态，音频不再次读取输入。修复旧 Speed/100、Speed/120 飞行声音归一化，以及视觉 Quality Off 关闭飞行声音的问题。
- 统一通讯 ducking 和音乐/环境/飞行/战斗/通讯/UI 分组音量。保留世界声音 12 路预算，持续舰船声音也计入；总活跃声源不越过当前 32 路真实声部设置。
- 保留唯一监听器、事件去重与浮动原点修正；镜头只改变已有声音权重。暂停保持世界/对白位置，UI 继续响应；跳过、结算和重开清除旧循环、队列和淡变。
- 保留 Unity 6000.5.10f1、URP 17.5.0、2000 舰、剧情与字幕长度及现有玩法；玩家只播放本地音频。
