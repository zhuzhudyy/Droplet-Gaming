## 新活动边界的独立计算

`Fleet2000Pipeline.cs` 及保存后的新任务配置使用警告半径 5,900 m、恢复边界 6,500 m，任务中心为 **(93.5415, 65.564, 2501.823)**。这是舰心范围的中心；不改宏观太阳系坐标，也不挪动舰阵或出生点。

遍历全部 2,000 个舰心，计算到新中心的欧氏距离；舰半径使用每一轴 `max(abs(shipBounds.min), abs(shipBounds.max))` 的向量长度，覆盖舰体包围盒相对枢轴的最远角。舰体 Y 范围不对称，因此这里采用 31.659353499 m 的枢轴包络半径，而非较小的半包围盒对角线。

|---|---:|

| 最远舰之一 | FS1C01R01 |
| 保守完整舰体枢轴半径 | 31.659353499 m |

## 90 分钟任务时限的 Boost 情景估算

实际 `FleetMission_2000.asset` 为 **5,400 秒（90 分钟）**，maxCruiseSpeed=52 m/s，boostMultiplier=3，最高 Boost 速度仍为 **156 m/s**；加速度仍为 45 m/s²。本复核没有修改水滴速度、尺寸、朝向或运动代码。

从同一 2,000 条姿态独立重建两层、100 条纵列的往返蛇形遍历，并把出生点至第一目标的路段计入，总长度再次得到 **458,685.207920040 m**。这是可复现的非最优直线分段路线；反向、转弯和瞄准另给时间预算，并非实跑路径。

| Boost 情景预算 | 秒 |
|---|---:|
| 全部路段按 156 m/s 计算的纯移动时间 | 2,940.289794359 |
| 99 次换列 × 3 秒 | 297 |
| 2,000 个目标 × 0.5 秒对准余量 | 1,000 |
| 上述合计再乘 1.15 余量系数 | **4,872.883263513** |
| 相对实际 5,400 秒时限剩余 | **527.116736487** |

90 分钟可覆盖这个以持续 Boost 为基础、给定转向/瞄准余量的估算。保守之处在路线及附加余量；**156 m/s 的持续 Boost 假设本身不是普通游玩速度的保守下界**，不能据此保证玩家必定清空 2,000 艘。没有实际完成 90 分钟通关，没有把转弯时间、加速时间或玩家操作分布作为已测数据。

按同一余量公式，90 分钟要求纯移动阶段有效均速至少约 **134.960915 m/s**。若只以 52/156 m/s 两档作距离加权，52 m/s 巡航路程占比最多约 **7.79%**；这解释了为何较大比例巡航与 90 分钟预算不一致。全部按 52 m/s 的纯移动时间就约 **8,820.869383 秒**，尚未加转弯和对准。

原布局 JSON/Blender README 的 **8,940 秒**估算采用 60% 巡航路程、40% Boost 路程，有效均速 70.909091 m/s，数学计算仍然正确；它是保留的早期较慢情景建议，**最终 Unity 任务设置以新场景的 5,400 秒为准**。交付总报告应同时说明这项设计覆盖关系，不能写成导入器采用了 JSON 的推荐时限。
